# EaC v0.2 specification

Status: implemented semantics. Everything described here exists in the repository and is covered by
tests. Planned-but-unshipped ideas live in `docs/spec/v0.2-implementation-plan.md`.

## 1. Guarantees

v0.2 keeps every v0.1 guarantee and adds a normalization boundary.

- **Seekability** — any time can be evaluated directly. No frame-zero replay, no runtime cursor.
- **Determinism** — the same source produces the same IR, the same SVG, and the same frames.
- **Single writer** — one logical writer owns one property over one interval. Conflicts are errors.
- **Authoring-order independence** — relative operations resolve from the property value at their
  own start time, not from the order in which builder methods were called.

## 2. Versioning

`ExperienceIR` carries `version: "0.2"` and `irVersion: 2`. Serialized v0.1 IR is never silently
read as v0.2: `loadProject` rejects it with an explicit diagnostic that names v0.1 and tells the
author to rebuild from a v0.2 TypeScript source. TypeScript v0.1 sources remain source-compatible
where the API did not change and rebuild into v0.2 IR.

## 3. Node tree

`NodeIR` is a tree of `group`, shape, and `image` nodes. Every node owns timed local transform
properties (position, rotation, scale, opacity, depth); visual nodes additionally own normalized
appearance data.

World values compose from the parent:

```text
world matrix  = parent world matrix × translate(local position) × rotate(local angle) × scale(local)
world opacity = parent opacity × local opacity
world depth   = parent depth + local depth
```

The affine representation is the six-number row form `[a, b, c, d, e, f]`. `evaluateScene` flattens
visual leaves with composed world values before global z ordering, so a descendant of a group sorts
against leaves outside that group. Equal z resolves by scene start, then stable source path, then
node id. Group cycles are structurally impossible through the builder API and are still checked in
raw IR.

## 4. Normalized writes

Builders record immutable authoring operations; `build()` normalizes them per node and property into
time-ordered writes. Each write records node, property, start, duration, absolute start and target
values, easing, writer id, source operation, and the logical properties it controls.

Because arrays are sorted once at build time, evaluation never sorts per frame. The 30-node,
five-group, ten-second performance sanity test in `packages/checker/src/performance.test.ts`
evaluates all 301 frames well inside a two-second budget.

## 5. Motion

- Absolute (`moveTo`, `rotateTo`, `fadeTo`, `scaleTo`, `depthTo`, `colorTo`, `blurTo`) and relative
  (`moveBy`, `rotateBy`, …) forms.
- Easing is an explicit definition on the segment, not a renderer detail.
- `followPath` is **one** logical writer of the vector position property, so it never manufactures
  independent x/y conflicts. An overlapping `moveTo`, `moveBy`, or second `followPath` is a position
  writer conflict. Rotation stays independent.

Trajectories are fully specified deterministic geometry, accept normalized progress, and are directly
seekable. `ellipse`, `orbit`, `spiral`, and `wave` are absolute paths; `linear`, `bezier`, `cycloid`,
and `wave` move trajectories normalize from a start and end. `ellipse` takes `startAngle`/`endAngle`
(defaults `0°`/`360°`); a degenerate arc is a `RangeError`.

## 6. Composition

`sequence`, `parallel`, `delay`, and `stagger` build immutable `MotionPlan` values with an explicit
duration and operation list. `schedule(plan, { at })` lowers a plan to ordinary writes:

- `sequence` — cumulative offsets
- `parallel` — shared start, maximum child duration
- `delay` — fixed offset
- `stagger` — index-based fixed offsets over a stable input array

There is no scheduler and no hidden cursor. `presets` are small plans built from the same primitives.

## 7. Color and style

Colors normalize to a typed `ColorIR` RGBA value at the authoring boundary via `hex`, `rgb`, `rgba`,
or `normalizeColor`. Hex and CSS-style strings receive a deliberate conversion rather than renderer
passthrough. Style covers fill, stroke, stroke width, blur, shadow, and text attributes (font family,
size, weight, alignment, letter spacing).

## 8. Assets

Local image bytes resolve at the CLI/project boundary, not in core semantics. `resolveProjectAssets`
turns a `local` asset into an `embedded` asset with MIME type, base64 data, and intrinsic dimensions
where available. Safety rules:

- the path must stay inside the project root, lexically **and** after `realpath` (symlink escape is
  rejected)
- arbitrary remote URLs are rejected
- assets over 20 MiB are rejected

Unresolvable assets become `invalid` records with a reason, so the checker reports them instead of
the renderer crashing.

## 9. Audio

Audio clips are scene timeline records, not visual nodes. `scene.audio(path, options)` produces an
`AudioClipIR` with id, asset, start, optional duration, trim start/end, volume, and fade in/out.

- Only frozen project-relative WAV is supported. `resolveProjectAssets` parses RIFF/`fmt `/`data`
  chunks for PCM (format 1) and float (format 3) and records a deterministic source duration; other
  bytes become `invalid-audio` with `missing`, `unsupported-format`, or `invalid-reference`.
- Path safety is identical to image assets.
- `audioClipDuration` resolves the effective clip length from explicit duration, else from the trim
  window, else from the source duration.
- The checker validates asset resolution, volume in `[0, 1]`, ordered in-bounds trim, playback that
  fits the scene, and non-negative fades that fit the clip, under `eac::audio::*` ids.
- `eac render` muxes checked audio into the MP4 through ffmpeg with `atrim`, `volume`, `afade`,
  `adelay`, and `amix`, padded and trimmed to the experience duration. `buildEncodeArguments` is a
  pure function so the argument vector is unit-tested without invoking ffmpeg.
- No waveform analysis, microphone input, or simulation. The HTML preview is silent and says so.

## 10. Renderer boundary

Property and hierarchy evaluation live behind the renderer-neutral `evaluateScene` API. The SVG
renderer only lowers evaluated leaves: affine transforms, typed RGBA colors, opacity, blur/shadow,
text attributes, and resolved image assets. PNG uses resvg through bounded workers; MP4 uses the PNG
sequence plus ffmpeg.

## 11. Checker

The checker consumes normalized IR and walks nodes recursively. Namespaced diagnostics cover units,
timelines, geometry, scale, easing, trajectories, hierarchy, color/style, assets, composition inputs,
audio, writer conflicts, unsupported property kinds, dependency cycles, sampled transforms, and
approximate AABB overlap. Conflict diagnostics include a text timeline naming both writers and the
overlapping interval. Structurally unsafe scenes skip sampling. AABB checks run on evaluated world
transforms and stay explicitly approximate.

## 12. CLI

`eac help`, `guide`, `docs` (categorized, searchable, with trajectory subtopics), `check --ci`,
`inspect` (node tree, counts, z values, writer intervals, audio clips, asset dependencies,
validation; `--json` for the same structured snapshot), `preview` (seek, play/pause, frame step,
speed, keyboard controls over pre-rendered frames), `render` (`--frame` PNG or full MP4), `format`,
and `init`.

`format` and the `check` format gate resolve the project's own Prettier configuration, so CLI
formatting agrees with the repository format gate rather than with Prettier defaults.

## 13. Examples

`basic-motion`, `cycloid-depth`, `path-follow`, `group-transform`, `sequenced-motion`,
`styled-title`, `image-card`, `audio-sting`, and `showcase`. Each passes `eac check --ci`;
`showcase` combines groups, trajectories, composition helpers, typed color, a local image, and audio
at zero errors and zero warnings.

## 14. Not in v0.2

ReactiveProperty, SimulatedProperty, a second renderer, explicit property composition, orientation
along a path, non-WAV audio, and audio waveform analysis remain out of scope.
