# EaC v0.2 implementation plan

Status: implementation plan, not a claim that the listed APIs already exist.

## Baseline and CI

The repository already has CI for formatting, lint, strict TypeScript, unit tests, build,
benchmark-material regeneration, Docker smoke tests, dependency audit, and public v0.1 benchmark
evidence verification. The v0.2 baseline is green with 55 tests and the v0.1 example checker at
zero errors and warnings.

The published `bench/results/r3` tree and `benchmark-v0.1-main-r3` tag are immutable historical
evidence. v0.2 development must keep `pnpm bench:verify-public` green and must not rerun the old
formal experiment.

## 1. Current architecture

- `@eac/units` creates finite branded values for time, length, angle, opacity, and depth.
- `@eac/ir` stores four timed properties per flat object and directly seeks a property by scanning
  time-sorted segments.
- `@eac/core` is a small mutable authoring builder that emits the IR.
- `@eac/checker` validates units, timelines, geometry, writer conflicts, unsupported property kinds,
  dependency cycles, sampled transforms, and approximate AABB overlap.
- `@eac/renderer-svg` evaluates the same properties, sorts leaves by depth/source order, lowers to
  SVG, rasterizes with resvg, and encodes MP4 with ffmpeg.
- `@eac/cli` loads a project and exposes deterministic help/docs/check/inspect/preview/render/format.

The design is easy to test, but high-level operations currently have no normalization boundary,
scenes are flat, colors are untyped strings, and the renderer knows how to evaluate authoring IR.

## 2. Technical stack

Keep the TypeScript monorepo, strict compiler settings, Vitest, resvg, worker-thread PNG pipeline,
and ffmpeg. No dependency is needed for the core v0.2 semantics.

Benefits: preserves type safety and package boundaries, avoids supply-chain/maintenance cost, keeps
tests fast, and makes deterministic math reviewable. Drawbacks: matrix, color, path, asset, and audio
normalization must be implemented and tested locally; resvg remains the only renderer proving the
current boundary. A second renderer is still deferred.

## 3. Proposed v0.2 IR

- Explicit schema metadata: source version `0.2` and numeric `irVersion`.
- `NodeIR` becomes a tree of shape, image, and group nodes.
- Every node owns timed local transform properties: position, rotation, scale, opacity, and depth.
- Visual nodes additionally own normalized appearance/style data.
- Motion segments carry an easing definition and logical writer metadata.
- Renderer-neutral evaluation produces flattened evaluated leaves with composed world transforms,
  world opacity, world depth, geometry/style, and stable source paths.
- Audio clips are scene timeline records rather than visual nodes.

Existing TypeScript v0.1 source examples remain source-compatible where practical and rebuild into
v0.2 IR. Serialized v0.1 IR receives an explicit compatibility path; it is never silently treated as
v0.2.

## 4. Timeline normalization

Core builders first record immutable authoring operations. `build()` normalizes them per
node/property into stable, time-ordered writes before checker or renderer use.

Each normalized write records:

- node and property
- start and duration
- absolute start and target values
- easing
- writer id and source operation
- logical properties controlled by the operation

Relative operations resolve their start value by evaluating all earlier-time operations at `at`, not
from a mutable call-order cursor. Same-start/overlapping ambiguity remains deterministic for
diagnostics but is invalid under the single-writer rule. Normalized arrays are sorted once, avoiding
per-frame sorting.

## 5. Group transform semantics

Groups preserve child-local coordinates. For each node:

```text
world matrix = parent world matrix × translate(local position) × rotate(local angle) × scale(local)
world opacity = parent opacity × local opacity
world depth = parent depth + local depth
```

Matrix multiplication uses a documented 2D affine representation. Evaluated visual leaves are
flattened before global z sorting so descendants can be ordered consistently with leaves outside the
group. Equal z is resolved by scene start, stable source path/declaration order, then node id. Group
cycles are structurally impossible through the primary builder API and are still checked in raw IR.

## 6. Follow-path writer semantics

Position remains one vector property. `followPath` creates one logical position writer and therefore
does not manufacture independent x/y conflicts. An overlapping `moveTo`, `moveBy`, or another
`followPath` is a position writer conflict. Rotation remains independent unless a future explicit
orientation option is added.

Trajectory constructors produce fully specified deterministic geometry. Ellipse/orbit/spiral paths
are absolute paths; linear/Bézier/cycloid/wave move trajectories can normalize from a start and end.
All path math accepts normalized progress and is directly seekable.

## 7. Sequence, parallel, delay, and stagger

Composition helpers create immutable `MotionPlan` values with explicit duration and operations.
Applying a plan at an explicit time lowers it to ordinary writes:

- `sequence`: cumulative offsets
- `parallel`: shared start, maximum child duration
- `delay`: fixed offset
- `stagger`: index-based fixed offsets over a stable input array

There is no runtime scheduler or hidden timeline cursor. Presets are small plans implemented through
the same public deterministic primitives.

## 8. Renderer implications

Property and hierarchy evaluation move behind a renderer-neutral evaluated-scene API. The SVG
renderer only lowers evaluated leaves. Affine transforms, typed RGBA colors, opacity, blur/shadow,
text attributes, and resolved image assets are mapped at this boundary. PNG and MP4 continue to use
the SVG output and bounded workers.

Final local image bytes are resolved at the CLI/project boundary and represented as explicit MIME +
base64 asset data for rendering; arbitrary remote URLs are rejected. This keeps file I/O and data URI
construction outside core semantics.

## 9. Checker implications

The checker consumes normalized IR and recursively walks nodes. It gains feature-specific
namespaced diagnostics for scale, easing, paths, hierarchy, color/style, assets, composition inputs,
and audio. Conflict messages use writer metadata and a text timeline. Unsafe structural errors skip
sampling. AABB checks operate on evaluated world transforms and remain explicitly approximate.

## 10. Audio feasibility

Audio is feasible after the asset boundary is stable. The planned minimum is a local frozen clip
reference with start, trim/duration, volume, and fade timing, plus ffmpeg mux during full MP4 render.
No waveform analysis, microphone input, or simulation is included. If portable media metadata
validation cannot be made reliable without adding a large dependency, known timeline/volume/asset
checks and one end-to-end mux path will ship while clip-bound checks remain documented as limited.

## 11. Compatibility and risks

- The node-tree and typed-color changes are the largest source/IR migration risks.
- Existing hex/CSS color strings should have a deliberate compatibility conversion, not renderer
  passthrough.
- Serialized v0.1 IR needs an explicit loader decision.
- Local assets require a stable project root and path traversal protection.
- Group depth flattening must not accidentally change v0.1 flat ordering.
- Exact final source artifacts under `bench/results/r3/artifacts` remain excluded from formatting so
  their published hashes stay valid.
- Performance must avoid sorting segment arrays on every frame and avoid history replay.

## 12. Test strategy

Each vertical slice adds unit tests before or with implementation. Required coverage includes normal,
invalid, boundary, empty, non-finite, and conflicting cases. Checker tests assert diagnostic ids and
repair guidance. Renderer tests use targeted SVG structure and deterministic byte/hash checks rather
than giant snapshots. Integration examples must pass `eac check --ci` and representative frame/full
renders. A 30-node, five-group, 10-second scene records a performance sanity result.

## 13. Directory and responsibility changes

- `packages/ir`: easing, trajectory math, normalization types, matrices, evaluated scene
- `packages/core`: authoring operations, nodes/groups, composition plans, presets, typed public API
- `packages/checker`: recursive normalized validation and asset/audio checks
- `packages/renderer-svg`: evaluated-node lowering, images/styles, audio-aware MP4 encoding
- `packages/cli`: project asset resolution, categorized docs, richer inspect, preview controls
- `examples`: integration and showcase sources/assets
- `docs/spec` and `docs/adr`: implemented semantics and decisions

Files remain focused below 300 lines; new concerns receive dedicated modules.

## 14. Commit milestones

Commits follow coherent vertical slices: planning; easing/scale/relative motion; paths/followPath;
groups; composition helpers; color/style/text; images/assets; CLI/preview; audio; examples/showcase;
performance/docs. Every milestone includes its tests and leaves the full validation suite green.
