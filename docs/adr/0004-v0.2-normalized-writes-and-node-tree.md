# ADR 0004: Normalize timed writes and evaluate a node tree

## Background

EaC v0.1 stores flat visual objects with four timed properties. v0.2 adds relative motion, easing,
paths, groups, scale, composition helpers, images, and richer style. Implementing each helper directly
inside evaluators and renderers would fragment semantics and weaken conflict checking.

## Problem

The system needs one representation that preserves direct seeking, single-writer diagnostics,
hierarchical local coordinates, renderer neutrality, and authoring-order independence.

## Options

1. Keep flat objects and teach every consumer each new helper.
2. Store a mutable runtime timeline cursor and replay operations.
3. Record authoring operations, normalize them into explicit writes, then evaluate a renderer-neutral
   node tree directly at any time.

## Decision

Adopt option 3.

Relative operations are normalized from the property value at their start time. Composition helpers
lower to explicit intervals. Follow-path is one logical writer of the vector position property.
Groups use parent-world × local affine composition; opacity multiplies and numeric depth adds.
Evaluation flattens visual leaves with composed world values before stable z ordering.

## Reasons

- One normalization boundary keeps helper semantics out of renderers.
- Explicit writes retain precise conflict diagnostics.
- Direct evaluation remains seekable and does not replay from frame zero.
- Node-local properties and world evaluation cleanly separate authoring from rendering.

## Benefits

- New helpers share the same checker and evaluator.
- Nested groups remain deterministic and testable.
- Renderers consume a smaller evaluated surface.
- Sorted normalized writes can be reused across frames.

## Drawbacks

- Build normalization is more complex than the v0.1 mutable segment builder.
- Raw hand-authored IR needs stronger validation.
- Relative operations that overlap another writer are invalid; their diagnostic representation must
  still be deterministic.

## Revisit conditions

Revisit only when adding a second renderer, explicit property composition, ReactiveProperty, or
SimulatedProperty. Those features may require a broader evaluation graph but must not silently change
v0.2 timed semantics.
